## Why

mvnex's core promise is "enhance Maven, don't replace it", yet today it ships as a separate native C++ binary that must be built per-platform (CMake, cpr/libcurl, replxx, MSVC runtime quirks) and installed out-of-band. Delivering the same workflows as a Maven plugin lets users get them with nothing but Maven (`mvn ex:init`, `mvn ex:add lombok`), resolves through Maven's own plugin/repository infrastructure, runs anywhere Maven runs, and removes the cross-platform native build entirely.

## What Changes

- Introduce a Java Maven plugin `com.sebas3261:ex-maven-plugin` (goal prefix `ex`) that reproduces every current behavior of the C++ CLI:
  - `ex:init` goal — project scaffolding (validation, package derivation, `pom.xml` + `Main.java` generation, Maven Wrapper generation, `--no-wrapper` equivalent, existing-directory protection, interactive prompting for missing values).
  - `ex:add` goal — dependency expression parsing, remote resolution (Sonatype Central search, Maven Central search, deps.dev), candidate ranking, stable-version selection, interactive disambiguation with "Search again", duplicate detection, format-preserving `pom.xml` insertion, and post-edit project validation.
  - `ex:help` goal — generated by maven-plugin-plugin; replaces `mvnex --help` / `mvnex <command> --help` / `mvnex --version`.
  - `setup` goal (new, no C++ equivalent) — run once as `mvn com.sebas3261:ex-maven-plugin:<version>:setup`; creates the user's `settings.xml` if missing, adds a `<pluginGroups>` section if needed, and registers `com.sebas3261` so the short `ex:` prefix works. `init`/`add` log a one-line tip pointing to it when the group is not configured.
  - `ex:uninstall` goal (new, no C++ equivalent) — the inverse of `setup`: removes only the `com.sebas3261` `<pluginGroup>` entry from the same settings file and leaves every other byte untouched, including the now-empty `<pluginGroups>` element.
- **BREAKING**: Command-line surface changes from `mvnex <command> [args] [--options]` to `mvn ex:<goal> -Dex.<param>=<value>`. Positional arguments become named parameters (e.g. project name → `-Dex.name`, dependency list → `-Dex.deps`, comma-separated).
- **BREAKING**: Remove the C++ implementation (`src/`, `CMakeLists.txt`, `.vscode/c_cpp_properties.json`) and the CMake-based CI/release workflow; replace with a Maven build that publishes the plugin.
- Terminal UX moves from ANSI-styled output and arrow-key selectors to Maven's logger and Maven's interactive prompter; batch mode (`-B`) becomes a first-class non-interactive path with deterministic failure messages.
- Behavior that is meaningless inside a running Maven (e.g. "Maven is not installed" warnings, shelling out to `mvn`/`mvnw` for validation or wrapper generation) is replaced by in-process equivalents. All such deltas are enumerated in `design.md`.
- Update `README.md`, `docs/ARCHITECTURE.md`, and `CLAUDE.md` for the plugin form.

## Capabilities

### New Capabilities
- `project-init`: Creating a new standard Maven project — inputs, validation rules, defaults, interactive/batch collection, generated file layout and content, Maven Wrapper generation, and output.
- `dependency-add`: Adding dependencies to an existing project — dependency expression grammar, version/scope rules, locating the target `pom.xml`, duplicate detection, POM insertion rules, ambiguity handling/selection, post-edit validation, and result reporting.
- `dependency-resolution`: Turning a search term or coordinate into an exact `groupId:artifactId:version` — providers, endpoints, concurrency/first-result semantics, candidate filtering and ranking, pre-release detection, stable/latest version selection, version-existence checks, timeouts, and error classification.
- `plugin-setup`: Registering and unregistering the plugin group in the user's Maven `settings.xml` (`setup` / `uninstall`) — target file location (`-s`, symlinks), creation of a new file, detection of an existing registration (ignoring comments), format-preserving insertion and removal rules, backup/atomic write and model-equality safety checks, and the setup tip shown by other goals.
- `plugin-distribution`: Packaging and delivering the tool as a Maven plugin — coordinates and goal prefix, goal/parameter surface, help/version, Java/Maven baselines, build and test pipeline, release publishing, and removal of the native CLI.

## Impact

- **Code**: All of `src/` (C++) is replaced by a Java source tree under the plugin module (`src/main/java`, `src/main/resources`, `src/test/java`, `src/it`). `CMakeLists.txt` and `.vscode/c_cpp_properties.json` removed.
- **Build/CI**: `.github/workflows/build.yml` switches from CMake on three OSes to `mvn verify` (unit + integration tests) on a JDK/OS matrix; tagged releases publish the plugin instead of zipped native binaries.
- **Dependencies**: Drops replxx, cpr, libcurl. Adds Maven plugin API and Maven Resolver 1.9.27 API/SPI (provided scope; all HTTP goes through Maven's own resolver transport, so no HTTP library is added), maven-plugin-annotations, plexus-interactivity-api (prompter), a JSON parser, plus test-only JUnit, WireMock, maven-plugin-testing-harness, and maven-invoker-plugin.
- **Users**: Invocation syntax changes (see BREAKING above). The `setup` and `uninstall` goals write to the user's `~/.m2/settings.xml` (or the `-s` file), always with a timestamped backup when modifying an existing file; `uninstall` touches nothing but this plugin's `<pluginGroup>` line. Generated projects and POM edits remain byte-for-byte equivalent to the C++ output so existing projects are unaffected.
- **External services**: the search APIs (`central.sonatype.com`, `search.maven.org`, `api.deps.dev`) are unchanged. Repository lookups (version listings, POM checks) now go to Maven Central through the user's configured mirrors instead of directly to `repo1.maven.org`. Proxies come from `settings.xml`, then libcurl-style environment variables, then JVM properties.
- **Docs**: `README.md`, `docs/ARCHITECTURE.md`, `docs/VISION.md` (distribution section), `CLAUDE.md`.
